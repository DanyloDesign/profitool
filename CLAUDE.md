# Profitool — инструкция для агента

Интернет-магазин строительного инструмента. Личный проект владельца, Jira и тикеты **не нужны**,
но `docs/dev/` вести обязательно.

Отвечать владельцу по-русски. Интерфейс сайта — украинский и русский.

---

## Запуск

```bash
pnpm install
pnpm dev          # http://localhost:3000 → редирект на /ua
pnpm build        # прод-сборка, 110 страниц
npx tsc --noEmit  # типы
```

Node 24, pnpm 10. Для перерисовки картинок нужен Blender 5.2 LTS (`brew install --cask blender`).

С 2026-09-21 проект собирается и на Windows: Node и Git через winget, pnpm через `npm i -g pnpm@10.6.5`.
Скриншоты и сквозная проверка: `tools/shots/` (см. README там же), `node tools/shots/smoke.mjs`
гоняет корзину, оформление, фильтры, тему и мобильный ящик на запущенном сервере.

### i18n: функции не пересекают границу server → client

Словарь содержит функции склонения (`dict.stock.low(2)`), а React не сериализует функции
в props клиентских компонентов. Поэтому вниз уходит **только строка локали**:

```tsx
// серверный компонент
const dict = getDict(locale);        // можно

// клиентский компонент
const { locale, dict } = useI18n();  // берёт из LocaleProvider
```

Никогда не передавать `dict` пропсом в компонент с `"use client"`. Исключение — `Footer`,
он серверный.

### Фильтры живут в URL

`src/lib/shop.ts` → `parseQuery` / `queryToParams` / `applyQuery`. Состояние каталога целиком
в `searchParams`, поэтому ссылка на отфильтрованную выдачу работает и кнопка «назад» тоже.
Компоненты, которые читают `useSearchParams`, обязаны быть обёрнуты в `<Suspense>`.

### zustand: селектор должен возвращать стабильную ссылку

```tsx
const items = useCart((s) => s.items);                    // да
const slugs = useCart((s) => s.items.map((i) => i.slug)); // нет, бесконечный цикл
```

Это уже ломало страницу сравнения. Производные массивы считать после подписки.

Сторы читают localStorage после монтирования, поэтому счётчики и состояния показываются
через `const mounted = useMounted()` из `src/lib/use-mounted.ts`, иначе разъезжается гидратация.
Не писать `useEffect(() => setMounted(true), [])`: линтер React считает это ошибкой.

`backdrop-filter`, `filter` и `transform` на предке делают его содержащим блоком для `position: fixed`.
Поэтому размытие шапки вынесено на отдельный слой, иначе меню внутри шапки схлопывается по её высоте.

## Дизайн-система

Спецификация: `DESIGN.md`. Реализация: `src/app/globals.css`, блок `@theme`. Tailwind v4, конфиг-файла нет.

Цвета: `ink-900` (фон) … `ink-600`, `bone` (текст), `bone-dim`, `bone-faint`, `signal` (заливка кнопок,
текст на ней только чёрный), `signal-text` (акцентный текст), `stock`, `warn`. Старый `#FF4A00` выведен.

Шрифты: **Unbounded** на заголовки и цены (`font-display`, утилиты `t-hero`, `t-h1`, `t-section`, `t-h2`,
`t-h3`, `t-price`), **Golos Text** на всё остальное (`font-ui`). Моноширинного нет. Капса нет.
`t-tag` и `t-eyebrow` — служебные подписи, меньше 14px текст не делать.

Скругления: кнопки, поля и чипы полные, миниатюры 18px. Панелей и карточек-подложек нет, блоки
разделяют волосяные линии `--hair`. Острых углов не делать.

Готовые утилиты, свои не плодить: кнопки `signal-btn`, `ghost-btn` (размер `btn-lg`, `btn-sm`),
`icon-btn` (44px), поля `field`, `field-area`, `check`, `radio`, чип `chip`. Высота шапки в
`--header-h`, отступы страницы в `--gutter`, ни того ни другого в пикселях не дублировать.

**Две темы.** Светлая с чисто белым фоном по умолчанию (решение владельца 2026-09-21), тёмная включается кнопкой в шапке. Компоненты
про тему не знают: они берут токены, а светлые значения лежат в `:root[data-theme="light"]`. Свои цвета
в компоненты не писать, только токены. Выбор хранится в `localStorage` (`profitool-theme`), атрибут
ставит скрипт из `<head>` до отрисовки. Новый цвет добавлять в оба набора и мерить контраст
(`node tools/shots/contrast.mjs`).

## Картинки

Две независимые системы, не путать.

**Товары** — настоящие фото, `/public/products/{tool}-{brand}-photo.png`, отдаёт `imageOf()`.
Исходники в `public/products/real/*.jpg`, карта адресов в `tools/products/rozetka-ids.json`.
Пересобрать: `python3 tools/products/prepare_photos.py` (вырезает белый фон заливкой от краёв,
обрезает по товару, вписывает в квадрат 760×760).

**Иконки разделов** — стекло из Blender, `/public/products/{tool}-makita-glass.png`,
отдаёт `categoryIcon()`. Пересобрать:

```bash
blender -b -P tools/products/render_products.py -- --out public/products --style glass \
        --resolution 900 --samples 150
```

`tool` — одно из: `rotary_hammer`, `drill`, `grinder`, `circular_saw`, `sander`, `laser_level`,
`bit_set`, `helmet`. Связь «категория → tool» лежит в `src/data/taxonomy.ts`.

После любой перегенерации: `rm -rf .next/cache/images` и перезапустить dev-сервер, иначе Next
отдаёт старые оптимизированные копии. Имя файла менять нельзя — на него завязан кэш браузера;
если поменял содержимое, но не имя, чистить кэш обязательно.

Query-строки в `src/*` у `next/image` не работают без `images.localPatterns` в конфиге —
проще дать файлу новое имя.

## Каталог

`src/data/products.ts`, 49 позиций. Добавить товар:

1. Дописать объект в массив. Обязательные поля смотреть в `src/data/types.ts`.
2. `category` — slug из `taxonomy.ts`, `brand` — оттуда же, `platform` — только для аккумуляторных.
3. `key` — параметр, который решает при выборе, показывается на карточке.
4. Ярлыки характеристик живут в `specLabels`; нового ключа нет — добавить в `SpecKey` и в словарь.
5. Картинка подхватится сама по паре «категория + бренд».

Модели и характеристики брать настоящие. Отзывов и рейтингов в проекте нет намеренно:
без реальных данных они подрывают доверие.

## Что осталось

- Страницы брендов и раздел «сервис» не сделаны: в меню на них ссылок нет.
- Пара фото подобрана приблизительно: поиск отдавал рекламные баннеры вместо packshot.
  Проверять глазами через контактный лист перед сдачей.
- Заказ никуда не уходит, оплата не подключена: чекаут заканчивается экраном с номером.
- Вход и регистрация только рисунок: формы проверяют ввод и говорят, что кабинет не работает.
- Из макетов сознательно не перенесено: отзывы и оценки (правило «без реальных данных»), полоса
  «ремонт, гарантия, возврат» на главной (владелец её забраковал), «оплата частями», «купить в
  один клик», «повідомити про наявність» (функций нет). Вернуть по слову владельца.
- Захардкоженных размеров осталось около 100 строк (`text-[..]`, `h-[..]`). Перевод на токены не завершён.
- Lighthouse не прогонялся. Контраст обеих тем замерен формулой WCAG, таблица в `DESIGN.md`.

## Работа

Коммиты: английский, тип-префикс со скоупом, например `feat(catalog): battery platform filter`.

Каждая заметная работа описывается в `docs/dev/NNN-slug/` четырьмя файлами: `request.md`
(дословная просьба владельца), `proposal.md` (что и почему), `plan.md` (шаги),
`implementation.md` (что вышло). Формат взят из рабочего репозитория владельца.

Любую правку вёрстки проверять скриншотом в браузере на 1512px и на 390px. Владелец смотрит
глазами и оценивает строго, отчёт «сделано» без картинки не принимается.
