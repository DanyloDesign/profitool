# 012 · Статична версія сайту на GitHub Pages

## 1. Request
Дизайнер (2026-09-27): зібрати сайт так, щоб його можна було скинути іншому дизайнеру, а той відкрив його в браузері. Вибрано GitHub Pages: адреса https://danylodesign.github.io/profitool/, публічна.

## 2. Proposal
Розглянуто GitHub Pages, Vercel і zip-архів. Вибрано Pages: публікацію я роблю сам через gh, сайт оновлюється після кожного push у master. Vercel вимагав би входу в акаунт, а zip-архів — локального сервера в того, хто відкриває.

## 3. Plan
- `next.config.ts`: з `GITHUB_PAGES=true` збирається статичний експорт з basePath `/profitool`. Без прапорця конфіг старий.
- Каталог і пошук читають `?sort`, `?brand`, `?page`, `?q` у браузері (`catalog-view.tsx`, `search-view.tsx`), бо в статиці сервер параметрів не бачить.
- `src/lib/asset.ts` додає basePath до шляхів картинок і логотипа.
- `tools/pages/postexport.mjs`: плоскі імена сегментів передзавантаження, редирект кореня на `/ua/`, `.nojekyll`.
- `.github/workflows/pages.yml`: збірка й деплой.

## 4. Implementation
- Локальна збірка: 136 сторінок. Папку `out/` віддав під `/profitool/` на порту 4173 і перевірив через puppeteer.
- Перевірено: головна ua/ru, каталог з `?sort=cheap` (ціни ростуть), клік по бренду Makita (`?brand=makita`, 1 товар), `?page=2`, товар, пошук `?q=makita` (12 результатів), перехід по категорії. Битих картинок немає, помилок у консолі немає. Скриншоти в `shots/`.
- Знайдено й виправлено: Next 16 запитує `__next.X.__PAGE__.txt`, а експорт кладе файл у `__next.X/__PAGE__.txt`. Через це були 404 на кожній сторінці.
- Відома особливість: у статичному HTML каталог і пошук спершу рендеряться без параметрів, після завантаження JS список фільтрується. На повільному з'єднанні може мигнути.
- Dev-режим після рефакторингу каталогу вручну не перевірявся: dev-сервер зупинено через брак пам'яті.
